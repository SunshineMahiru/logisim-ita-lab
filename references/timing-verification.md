# 同步时序电路：测试与验收

> 组合逻辑那套「门级仿真器对拍真值表」对时序电路不够用：结果同时取决于**时钟沿、复位极性、
> 采样时刻**三件事，而这三样只有真实引擎跑得准。本章把实验3（计数器 / 移位寄存器 / 乘法器 /
> 寄存器堆 / 数字时钟）踩过的坑沉淀成可直接照做的测试规程。

## 1. 测试目标

1. **功能正确**——按题面功能表或测试向量逐拍推进，输出与期望逐行一致。
2. **时序正确**——复位、装载、计数/移位、保持四类动作位于正确的拍子上，不多一拍也不少一拍。
3. **结构完好**——无意外悬空端点、无意外短接；引脚、`<main>`、`<appear>` 未被改动。
4. **可独立加载**——文件不含外部库引用，不缺子电路定义，目标版本 Logisim 能单独打开。

## 2. 前置条件

| 项 | 要求 | 检查方式 |
|---|---|---|
| JDK | 8 以上 | `java -version` |
| Logisim-ITA | 与平台同版本 | `java -jar "$LOGISIM_JAR" -version` |
| 模板 | 原始未改动目录 `myshixun/labN.M.circ` 只读，不就地改 | 生成物一律写到「已完成目录/myshixun/」 |
| 期望表 | 题面 docx「测试数据」段，逐列核对表头顺序与进制 | 先整成列表/JSON，禁止手抄 |
| 驱动 | `scripts/CircRun.java` + `scripts/runner.py`（先 `javac` 编译） | 见 3.4 |
| 目录 | 生成脚本 `build/build_labNM.py`、验证脚本 `build/test_labNM.py` 一对一命名 | 便于回归 |

**驱动编译**（一次性）：

```bash
javac -encoding UTF-8 -cp "$LOGISIM_JAR" -d "$LOGISIM_TOOLS" \
      scripts/CircRun.java scripts/Conn.java scripts/Dump.java
```

运行期通过环境变量指路，避免写死绝对路径：

```bash
export LOGISIM_JAVA="<jdk>/bin/java"      # 可省略，默认取 PATH 中的 java
export LOGISIM_JAR="<解压目录>/Logisim-ITA-2.16.2.0/Logisim-ITA.jar"
export LOGISIM_TOOLS="<编译输出目录>"      # 默认 tools
```

## 3. 执行步骤

### 3.1 固化期望值

从 docx 提取「测试数据」表，写成脚本里的字面量表，**同时记录三件事**：

- 列顺序（如 `Cnt LD CLR ENP ENT D Q RCO`）与位宽；
- 进制（`c` / `3b` 是十六进制，别当十进制）；
- 采样语义——表里的输出是**时钟沿之前**还是**之后**的值。这一步不确定，后面全白做（见 3.5）。

### 3.2 生成电路

```bash
python build/build_labNM.py            # 只增不改，写入「已完成目录/」
```

### 3.3 结构自检（先于功能测试）

```bash
java -cp "$CP" Conn  <目标.circ> [电路名]   # 列出悬空端点
java -cp "$CP" Dump  <目标.circ> [电路名]   # 打印每个组件的实际端口坐标
java -cp "$CP" ErrLoad <目标.circ>          # 捕获加载错误的真实文案
java -jar "$LOGISIM_JAR" -tty stats -nosplash <目标.circ>   # 能列出组件统计即为可加载
```

`Conn` 的期望输出：只剩**刻意悬空**的端点（D 触发器的 `~Q`、模板自带的装饰隧道）。
出现 `UNCONNECTED ... (in)` 一律视为缺陷，先修结构再谈功能。

### 3.4 功能对拍

```bash
python build/test_labNM.py        # 全表逐行比对 + 追加用例
```

`runner.py` 的用法（`cmds` 为命令序列，返回每行 `snap` 的字典）：

```python
from runner import run, setline
cmds = [setline({'CLR_L': 0, 'S1': 1, 'S0': 1}), 'snap', 'clk']
res = run('已完成目录/myshixun/lab3.2.circ', 'SHRG4U', cmds)
res['snaps']   # [{'Q3': '0', ..., 'Q0': '0'}, ...]
```

命令语义：`set` 用**逗号分隔**、名字带空格要加引号（`set "Write Enable"=1,"R1#"=0`）；
`snap` 打印全部输出引脚；`clk` 产生一个**下降沿**（`CLK 1→0`），`clkrise` 产生上升沿。

### 3.5 时序约定校准（最容易翻车的一步）

同一张表在四种假设下结果完全不同，**必须先确认哪一种才是平台的**：

```python
# 假设维度：sample ∈ {before, after} × edge ∈ {falling, rising}
# before = 设输入 → 读输出 → 打沿；after = 设输入 → 打沿 → 读输出
```

判定手段，按可靠性排序：

1. 拿平台**已通过 / 部分通过**的同类 `.circ` 当参照，同一张表跑一遍，看哪种假设能复现；
2. 用平台回报的「预期 / 实际」两列反推——若实际序列整体等于期望序列平移一行，就是采样点错位；
3. 都没有时，按题面语义选：题面写「在时钟边沿到来前……保持稳定」，通常意味着**沿前采样**。

实测结论（实验3）：寄存器堆、移位寄存器在「**沿前采样 + 一个下降沿**」下与平台表完全吻合；
乘法器若把「复位期间装入被乘数」写成依赖 `RST=1` 的那个沿，平台给不出这个沿，装载会静默丢失。

## 4. 预期结果

- `test_labNM.py` 输出行数 = 期望表行数 + 追加用例数，逐行 `OK`，末尾 `RESULT: ALL PASS`；
- 无 `>>ERR`（会指明是哪个引脚名或哪条命令出错）；
- `Conn` 的 `unconnected` 计数只包含刻意悬空项；
- `Dump` 打印的端口坐标与生成脚本里的假设一致（不一致说明端口规则记错了）。

## 5. 验收标准

| 编号 | 标准 | 判定方式 |
|---|---|---|
| A1 | 题面测试向量 100% 命中 | `test_*.py` 全行 OK |
| A2 | 覆盖每条分支：装载 / 保持 / 清零 / 计数回绕 / 极值（如 15×15、0×n） | 追加用例里逐条列出 |
| A3 | 状态序列与期望**逐拍**一致，不只是终值正确 | 每拍都 `snap`，不合并检查 |
| A4 | 结构自检无意外悬空 | `Conn` 输出 |
| A5 | 文件可独立加载（无外部库、无缺子电路） | `ErrLoad` 无输出 + `-tty stats` 正常 |
| A6 | 时序约定有明确依据（参照件或平台回报反推），不是猜的 | 3.5 的记录 |

A1~A5 全部满足才算交付；A6 存疑时必须在交付说明里写明假设。

## 6. 异常与边界情况

| 现象 | 最可能的原因 | 处理方式 |
|---|---|---|
| 整片输出 `X` | 隧道没挂在导线端点上；或端口根本没接线 | 见 7.1 的两条铁律，用 `Dump` 对齐坐标 |
| 某个网络恒为全 1 / `X`，且牵连一大片 | 导线端点压在别的隧道点上造成短接（选择端、使能端并排 10~20px 时高发） | 把选择/使能改成**垂直**引出，不要与数据端同一水平线 |
| `Register` 读出 `0xFFFFFFFF` | `EN`/`CLR`/`SET` 被常量直接接住 | 三个脚**全部悬空**，只接 `CLK` 与 `GATE`（实测有效） |
| 加载报 `required library file 'xxx.circ' is missing` | 文件里有 `<lib desc="file#...">` 外部库引用 | 删掉该 lib 与对应实例，或把被引电路内联成本文件的 `<circuit>` |
| 加载报缺子电路 / 空白电路 | `<main>` 指向的电路不存在；或 `<comp lib="8" name="X">` 没有定义 | 补 `<circuit name="X">`，实例改成不带 `lib` 的写法 |
| 状态整体平移一行 | 采样点或时钟沿数目与平台不一致 | 跑 3.5 的四象限 |
| 复位后该装入的寄存器永远是初值 | 装载逻辑依赖「`RST=1` 期间的那个沿」，平台没给 | 把装载条件改挂到正常的状态译码上（如 `C==0`），不要寄生在复位期 |
| 计数器不饱和、末态乱跳 | 到位后没有冻结（时钟门控或使能条件写错） | 用使能/多路选择冻结，时钟门控只作最后手段并单独验证 |
| 某一位总是错、其余位对 | 该位触发器的 `trigger` 被改过（`high`/`low` 电平敏感） | 全部统一为 `falling`，与模板一致 |

## 7. 生成铁律与执行顺序

### 7.1 `.circ` 文本编辑的两条铁律

1. **组件端口必须由导线引出**——把 Tunnel 直接压在门/触发器端口上**不导通**，必须
   `端口 ← 20px 导线 → 隧道`。
2. **隧道必须坐在导线端点上**——它只认「导线端点」，不认「组件端点」；反过来，导线**穿过**
   某个隧道点时也会连上，这正是短接的来源。

### 7.2 端口坐标

组件端口的实测坐标表见 `components.md`。新增组件前先 `Dump` 量一遍，再补进那张表。

### 7.3 执行顺序

`采集期望值 → 生成 → 结构自检 → 功能对拍 → 时序校准 → 全量回归`。
不要跳过结构自检直接跑功能：一个误短接会让几十行全部 `X`，把真正的逻辑错误淹没。

## 8. 参考实现：数字时钟（实验3.5）

可作为「大型时序电路」的参考形态。文件 200 KB / 1,367 元件 / 约 29 个 D 触发器 /
**零外部引用、零子电路实例**（这两点是有意为之，见下）。

| 模块 | 做法 |
|---|---|
| 6 个 BCD 位 | 每位 4 个 DFF，`Q' = ~LD & (EN ? Q+1 : Q)`；回绕用 `LD = (Q==limit) & EN`、`D=0`（同步装载），**不用 CLR**——`CLR` 是异步的，会同一拍清掉整条链 |
| 级联 | `ENT(高位) = 低位"到限" & 低位 ENT`；`SS0` 的 `ENT` 恒 1 |
| 装载校验 | `BAD = HH>23 ∨ MM>59 ∨ SS>59`；`INErr = LD·BAD`；`LDv = LD·~BAD`，六位的 `D` 取输入值、`LD = LDv ∨ 回绕` |
| 整点 LED | `START = (MM==59)·(SS==59)·~LDv`；第 7 片计 0→9；三色 = `step&7` 的格雷码（`R=~s1`，G/B 各三级门）；`LED_EN` 门控，非活动期三色拉 0 |

**两条踩出来的教训**：

1. **子电路实例可以用，但要逐项验证**。曾有「同一个 `CNTR4U` 作主电路 16/16、作实例却不计数」
   的现象；后来用学长留档的 `lab3.5.circ`（7 个 `CNTR4U` 实例）实测**能正常计数**，
   说明子电路本身没问题，问题出在当次的接线/端口映射。结论修正为：
   实例化后先单独打两拍看 `Q` 是否翻转，有问题就查 `<appear>` 的 `circ-port` 是否与内部 Pin 对齐、
   以及子电路内部 `CLK` 隧道是否真的由 Pin 驱动。
2. **`INErr` 这类组合输出只在 `LD=1` 期间有效**。验证时若先撤 `LD` 再采样，会误判成「恒 0」。
   正确做法：`set LD=1,...` → `snap`（此时读 INErr）→ `clk` → `snap`（读装载结果）。
